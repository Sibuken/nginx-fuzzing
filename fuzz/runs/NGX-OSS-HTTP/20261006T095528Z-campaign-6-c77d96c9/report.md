# Отчёт кампании NGX-OSS-HTTP

- Идентификатор: `20261006T095528Z-campaign-6-c77d96c9`
- Результат: кампания завершилась штатно по достижении плато покрытия
- Длительность: 14 533,5 с (около 4 ч 02 мин)
- Окно плато: 7 200 с; фактическое время без прироста покрытия: 7 346 с
- Контрольных точек покрытия: 45
- Предварительная проверка регрессий: 1 из 1 воспроизведён
- Найдено артефактов: 275 — 272 с симптомом `crash` и 3 с симптомом `slow`

## Краткий вывод

Все 272 findings с пометкой `crash` вызваны двумя классами сообщений UndefinedBehaviorSanitizer (UBSan), а не обнаруженными AddressSanitizer ошибками памяти. 227 артефактов относятся к арифметике над null-указателем при нулевом смещении в `ngx_write_file()`, ещё 45 — к передаче null-указателя в `ngx_copy`/`memcpy` при нулевой длине в `ngx_http_proxy_create_request()`.

Санитайзер намеренно завершает процесс при диагностике UB (код 77), поэтому libFuzzer записывает такой случай как `crash`. Все 272 соответствующих повтора без санитайзеров завершились с кодом 0. Дополнительно по одному входу каждого класса проверили на сборке с оптимизацией `-O2` и `_FORTIFY_SOURCE=2`, без ASan/UBSan: оба testcase обработаны за 28 мс, завершились с кодом 0 и не вызвали аварийного завершения harness. Это не подтверждает отсутствие любых последствий UB при всех компиляторах и конфигурациях, но обнаруженный санитайзерный «краш» на этой оптимизированной проверочной сборке не воспроизвёлся.

## Что вызвало findings

### `ngx_write_file`: 227 артефактов

UBSan указывает на `src/os/unix/ngx_files.c:208:34`: выражение `buf + written` вычисляется при `buf == NULL` и `written == 0`. Стек представительного артефакта `crash-05c4e04764588025aa72160480ef569df33843b4` проходит через `ngx_write_chain_to_file()`, `ngx_write_chain_to_temp_file()` и сохранение тела HTTP-запроса в `ngx_http_request_body.c`, включая обработку chunked-тела.

В этом случае размер записи равен нулю. UBSan диагностирует недопустимое по правилам C вычисление указателя; сам отчёт не показывает чтения или записи байтов через него. Нулевой размер объясняет, почему тот же вход завершился без аварии в сборках без UBSan. Дефект в исходном коде остаётся, но в исследованных данных нет признаков переполнения буфера, чтения/записи чужой памяти или удалённого исполнения кода.

### `ngx_http_proxy_create_request`: 45 артефактов

UBSan указывает на `src/http/modules/ngx_http_proxy_module.c:1367:23`: при подготовке запроса к upstream копируется URI с нулевой длиной и null-источником. Минимальный регрессионный вход `fuzz/regressions/NGX-OSS-HTTP/nonnull-zero-length.textproto` использует absolute-form URI с пустым путём и query delimiter.

Это нарушение контракта для null-указателя при вызове операции копирования, даже если длина равна нулю. Отчёт UBSan не показывает копирования ненулевого объёма или повреждения памяти. Представительный артефакт `crash-04ecb9c498c51a7067cba67df8db637a2a9fa5e1` также завершился без ошибки на оптимизированной проверочной сборке.

## Как проверялось воспроизведение

1. Сопоставлены сообщения и стеки sanitizer-логов: все 272 «краша» сводятся к двум строкам исходников и двум описанным классам UB.
2. Сопоставлены коды повторного запуска из manifest: все sanitizer-повторы завершались кодом 77, все повторы без санитайзеров — кодом 0.
3. Для независимой проверки выбраны реальные входы кампании: `crash-05c4e04764588025aa72160480ef569df33843b4` для `ngx_write_file()` и `crash-04ecb9c498c51a7067cba67df8db637a2a9fa5e1` для `ngx_http_proxy_create_request()`.
4. Оба входа исполнены по одному разу в HTTP fuzz harness, пересобранном с `-O2`, `_FORTIFY_SOURCE=2` и без ASan/UBSan. Каждый запуск занял 28 мс и вернул код 0; сообщения о падении или тайм-ауте не возникли.

Проверка подтверждает, что именно санитайзерные аварийные завершения не воспроизводятся на указанной оптимизированной конфигурации. Она не доказывает эквивалентность поведения при всех компиляторах, окружениях и конфигурациях nginx. Findings следует считать реальными замечаниями корректности C, но не подтверждёнными критичными уязвимостями по результатам этой кампании.

### Медленные входы

Все три артефакта `slow-unit-*` повторно завершились с кодом 0. Под санитайзером измеренное время одного исполнения составило 61, 84 и 73 мс соответственно. Устойчивое зависание или воспроизводимая деградация на этих входах не подтверждены.
