# Сводный отчёт по фаззинг-кампаниям nginx

Сводка по всем 17 сохранённым кампаниям: `NGX-OSS-HTTP` и `NGX-IF06`–`NGX-IF21`. Источники — manifests, `campaign.log` и индивидуальные `report.md` из `fuzz/runs`. Продолжительность — сумма времени кампаний, а не календарное время: часть запусков выполнялась параллельно.

## Структура каталога `fuzz`

```text
fuzz/
├── dict/           словари libFuzzer для интерфейсов
├── docker/         Dockerfile и Compose-конфигурация запуска
├── patches/        патчи к изолированной копии nginx для fuzz hooks и целей
├── regressions/    входы, сохранённые для повторной проверки известных находок
├── runs/           результаты кампаний: manifests, отчёты, логи и корпуса
├── scripts/        сборка, запуск кампаний, сбор покрытия и вспомогательные команды
├── seeds/          начальные входные данные для каждого интерфейса
├── suppressions/   каталог для конфигураций подавления диагностик (сейчас пуст)
├── targets/        harness-ы, описания и метаданные целей NGX-IF06–IF21 и NGX-OSS-HTTP
├── tests/          unit-тесты скриптов управления фаззингом
├── vendor-cache/   проверенные архивы сторонних сборочных зависимостей
├── README.md       инструкции по сборке, smoke-тестам и кампаниям
├── UPSTREAM.md     происхождение upstream-кода, фиксация версий и локальные адаптации
├── REPORT.md       этот сводный отчёт по результатам кампаний
└── upstream.lock.json  закреплённые версии и контрольные суммы зависимостей
```

`targets/` задаёт, какой код проверяет каждый интерфейс; `seeds/` содержит стартовые примеры, а `dict/` — подсказки для мутации входов. Во время кампании результаты и найденные входы сохраняются отдельно в `runs/`; подтверждённые regression-входы хранятся в `regressions/` для проверки при последующих запусках. `patches/` применяются только к копии nginx внутри сборки фаззинг-образа и не меняют рабочие исходники или production-сборку.

## Группы crash-findings и оценка

Все crash-артефакты сосредоточены в IF07 и NGX-OSS-HTTP. Число артефактов существенно больше числа первопричин: одно и то же сообщение UBSan повторялось для множества вариантов входных данных. Ниже причины объединены по симптомам и исходным операциям.

### NGX-IF07 — 11 200 артефактов

В `campaign.log` и индивидуальных sanitizer-логах обнаружены два класса UBSan-диагностик:

- **11 059 случаев — знаковый сдвиг при сборке DNS TTL.** Первый байт TTL сдвигается на 24 бита в выражении типа `int`; при значениях от 128 операция выходит за диапазон знакового типа. Это встречается в обработке A, SRV и PTR: строки 2197 и 2359, 2739 и 3304 в [`ngx_resolver.c`](src/core/ngx_resolver.c). Поле TTL затем хранится как `int32_t`, а отрицательное значение нормализуется в 0. Наблюдаемое последствие — некорректная обработка TTL/срока кэширования, а не запись по управляемому адресу или выход за границы буфера. TTL 0 сам по себе допустим в DNS; в кампании нет ASan-диагностики чтения или записи за границами, а все сохранённые sanitizer-findings при повторе без санитайзеров завершились с кодом 0. Это подтверждает отсутствие воспроизводимого падения без UBSan, но не отменяет дефект арифметики; его корректно считать проблемой корректности, для которой не показан эксплуатируемый примитив.
- **141 случай — null-указатель в сравнении нулевой длины.** На строке 3357 [`ngx_resolver.c`](src/core/ngx_resolver.c#L3357) `ngx_strncmp` вызывается с `name.len == 0` и нулевым указателем. UBSan проверяет контракт ненулевого аргумента, но при нулевой длине байты не сравниваются. Повторы без санитайзеров также завершились с кодом 0; ошибки адресации или порчи памяти не обнаружены.

Итак, IF07 содержит реальные замечания по определённому поведению C, но зарегистрированный `crash` здесь — fail-fast завершение UBSan (код 77), а не подтверждённое аварийное завершение обычного бинарника. Данные прогона не показывают переполнения буфера, повреждения памяти или выполнения кода. Оценка ограничена использованными harness и конфигурацией; она не доказывает безвредность всех возможных последствий неопределённого поведения.

### NGX-OSS-HTTP — 272 crash-артефакта и 3 slow-артефакта

- **227 случаев — арифметика указателя при нулевом размере записи** в `ngx_write_file()` (`src/os/unix/ngx_files.c:208`). Для операции размером 0 вычисляется `buf + written` при `buf == NULL`; чтение или запись байтов через этот указатель не наблюдались. Все sanitizer-повторы завершились с кодом 77, повторы без санитайзеров — с кодом 0. Представительный вход дополнительно проверен в сборке `-O2` с `_FORTIFY_SOURCE=2`, без ASan/UBSan: падение не воспроизвелось.
- **45 случаев — null-источник при копировании URI нулевой длины** в `ngx_http_proxy_create_request()` (`src/http/modules/ngx_http_proxy_module.c:1367`). Вход задаёт пустой путь в absolute-form URI. При нулевой длине байты не копируются; UBSan останавливает процесс на нарушении контракта аргумента. Повторы без санитайзеров завершились с кодом 0; представитель также не воспроизвёлся в оптимизированной проверочной сборке.
- **3 slow-артефакта** при повторе заняли 61, 84 и 73 мс каждый. Повторяемого зависания или длительной деградации не установлено.

Обе crash-группы в NGX-OSS-HTTP — диагностики UBSan для операций с нулевой длиной, а не наблюдавшиеся ASan-ошибки памяти. Отчёт кампании фиксирует отсутствие аварии при повторах без санитайзеров; для двух представительских входов также есть проверка оптимизированной сборки. Это достаточное основание не считать найденные симптомы подтверждёнными удалёнными memory-corruption уязвимостями, но не утверждение, что UB в исходниках не требует исправления.

### Краткий вывод об эксплуатируемости

В сумме зарегистрировано **11 472 crash-артефакта**, сведённых к четырём группам операций: разбор TTL, сравнение нулевой длины, арифметика указателя при нулевой записи и копирование нулевой длины. Во всех случаях симптом связан с fail-fast UBSan; для IF07 и NGX-OSS-HTTP повторы без санитайзеров завершились штатно. Ни одна из кампаний IF06, IF08–IF21 не сохранила crash-findings. На имеющихся данных эксплуатация с повреждением памяти или выполнением кода не подтверждена. При этом UBSan-замечания в исходном коде остаются и могут требовать исправления как дефекты корректности.

Подробности, входы и журналы повторного запуска сохранены в индивидуальных отчётах: [NGX-IF07](fuzz/runs/NGX-IF07/20261007T212722Z-campaign-1-ed50cba0/report.md) и [NGX-OSS-HTTP](fuzz/runs/NGX-OSS-HTTP/20261006T095528Z-campaign-6-c77d96c9/report.md). У остальных интерфейсов индивидуальные отчёты находятся рядом с `manifest.json` в соответствующих папках `fuzz/runs`.
