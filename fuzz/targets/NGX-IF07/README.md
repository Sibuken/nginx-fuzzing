# NGX-IF07 — обработка DNS-ответов

Бит 0 байта 0 выбирает транспорт (`0` — UDP, `1` — TCP), а бит 1 включает самоосвобождающийся пустой resolver waiter. В байтах 1..N находится DNS-ответ в wire-формате. Добавляемая при сборке обвязка проверяет корректный несжатый вопрос и создаёт соответствующий ожидающий узел resolver перед вызовом настоящего автомата состояний `ngx_resolver_process_response` в nginx. Это позволяет проверить разбор ответа без открытия сокета и без искусственного создания состояния после парсера.

Начальные примеры охватывают A, AAAA, CNAME, SRV, IPv4 PTR, NXDOMAIN, а также некорректные сжатие и длины. Для A/AAAA/PTR и ошибок включён waiter; для успешного SRV-ответа он намеренно отключён, поскольку callback запускает дочерние DNS-запросы. Деревья и очереди resolver, выделения памяти и кэш создаются заново и уничтожаются для каждого входа.
