# NGX-IF15 — автомат состояний блока заголовков HPACK HTTP/2

Цель передаёт произвольные байты HPACK настоящей функции nginx `ngx_http_v2_state_header_block`. Обвязка помещает вход в тело кадра HEADERS и повторяет его, разделяя данные на части по одному байту, по три байта или по размеру из входа, в корректных кадрах CONTINUATION. Для каждого выполнения создаются новые пулы nginx и динамическая таблица.

Цель проверяет декодер представлений блока, обработку Хаффмана и целых чисел HPACK, добавление, поиск и вытеснение записей динамической таблицы, а также CONTINUATION. Некорректный HPACK ожидаемо отвергается парсером; защита от ошибок, добавленная только при сборке, фиксирует отказ, не запуская формирование ответа и финализацию.

Начальный заголовок HEADERS создаёт обвязка, поэтому `ngx_http_v2_state_headers` не проверяется. Парсер запускается с NULL вместо потока: это намеренно исключает создание запроса, поэтому проверка HTTP-заголовков и семантики pseudo-заголовков не входит в область цели. Заголовки CONTINUATION корректны и используют тот же ID потока. Это цель для состояния блока HPACK, а не полноценный фаззер запросов HTTP/2.

Запуск:

```sh
./fuzz/scripts/fuzz.sh smoke NGX-IF15
```

В начальных примерах есть блок с индексом из статической таблицы и блок с добавлением динамической записи, за которым следует ссылка на неё. Область покрытия зафиксирована в `target.json`.
