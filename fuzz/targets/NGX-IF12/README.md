# NGX-IF12 — управляющие кадры HTTP/2

Цель разбирает кадры HTTP/2 в wire-формате через настоящие обработчики nginx для заголовков кадров, а также SETTINGS, PING, GOAWAY и WINDOW_UPDATE на уровне соединения. Каждый вход повторяется целиком и по трём схемам фрагментации. Несколько кадров можно объединить, чтобы проверить сохранение настроек соединения и состояния управления потоком.

Добавляемый только при сборке драйвер для каждого повтора создаёт новый пул nginx, очередь выходных кадров, конфигурацию HTTP/2-сервера и один минимальный активный поток (ID 1). Для WINDOW_UPDATE соединения он добавляет второй искусственный ожидающий поток. Это позволяет достичь переполнения окна потока, пробуждения потока с исчерпанным окном и очереди ожидающих, не переходя к разбору запроса. Поток 3 представлен закрытым узлом (есть в индексе, но активного потока нет), что отличает его от неизвестного ID. При трёхбайтовой фрагментации искусственное событие записи помечается отложенным, проверяя восстановление готовности без вызова обработчика. Канонический пример WINDOW_UPDATE использует второй ожидающий поток; при трёхбайтовом повторе callback записи первого потока потребляет увеличение окна, после чего проверяется, что итерация останавливается на нуле, а второй поток остаётся в очереди. Ожидаемые ошибки протокола завершают только текущий искусственный разбор, не запуская полное завершение сетевого соединения.

Тела DATA, HEADERS, PRIORITY и RST_STREAM здесь намеренно не принимаются. Для них нужна более полная модель запроса и дерева потоков; эти случаи относятся к отдельным специализированным целям.
