# NGX-IF21 — трейлеры ответа upstream HTTP/2

Обвязка создаёт искусственный контекст upstream после отправки заголовков ответа, помещает блок трейлеров HPACK в настоящие кадры HEADERS HTTP/2 и передаёт их функции nginx `ngx_http_proxy_v2_process_frames`. Бит 0 режима разделяет блок между HEADERS и CONTINUATION; бит 1 убирает END_STREAM; бит 2 — END_HEADERS; бит 3 добавляет перед ним однобайтовый DATA; бит 4 — DATA с padding; бит 5 — DATA с заведомо некорректным padding; бит 6 добавляет два кадра DATA; бит 7 задаёт END_STREAM у единственного предшествующего DATA. В режиме двух кадров бит 4 включает padding у первого, бит 5 — у второго. Байты расположены как полезная нагрузка кадра, необязательная длина padding, затем следующий кадр; за ними следует HPACK-блок. Байты padding — нули. В режиме одного кадра бит 5 задаёт длину padding 2, оставляя в кадре только один байт. Для режима `0x88` последовательность `0xff` и одного байта полезной нагрузки после закрывающего DATA — фаззинг-маркер, который вставляет ещё один DATA в том же потоке перед пустым HEADERS.

Обвязка потребляет DATA так же, как вызывающий фильтр тела upstream, прежде чем продолжить обработку кадров. ID потока фиксирован и соответствует активному потоку upstream.

Цель проверяет декодирование трейлеров HPACK, отклонение pseudo-заголовков, добавление элементов в список трейлеров, проверку END_STREAM, завершение CONTINUATION и переход от последовательных полезных нагрузок и padding DATA к HEADERS трейлеров, включая отказ при чрезмерном padding. Сокеты не создаются, управляющие кадры upstream не отправляются. Заголовки ответа моделируются как уже обработанные; DATA-последовательность создаётся искусственно, полный жизненный цикл тела ответа не фаззится. Также проверяется, что DATA с END_STREAM, с padding и без него, обрабатывается до отклонения следующих HEADERS трейлеров как кадра закрытого потока. Случай с маркером проверяет отклонение следующего DATA на этом закрытом потоке.

```sh
./fuzz/scripts/fuzz.sh smoke NGX-IF21 --max-len 16384
```
